# Verifying the cleaned repository

The original repository is cleaned in place. A complete private copy of the old
working directory and Git history is retained outside it, with a SHA-256 backup
inventory. Raw records, caches, per-example results and the license-pending
translated baseline are removed from the public working tree and Git index.
Local history is filtered to the reviewed paths, and historical versions of
the translated baseline are replaced by the public adapter. Commits affecting
only excluded files may disappear; retained commits have changed identifiers.

The directory and configured GitHub URL remain the same. **This local cleanup
does not update GitHub.** The separate private backup must never be published or
merged back into the cleaned history.

Run this from the repository before publishing a reviewed commit:

```bash
python scripts/verify_repository.py
python -m unittest discover -s scripts -p 'test_*.py' -v
```

The verifier requires the index to match `release_files.txt`, a committed working
tree, and no unreviewed untracked files. It checks every locally reachable commit,
including remote-tracking refs, for excluded paths, symlinks, credential/email
patterns and the known translated baseline. It refuses shallow or masked history.
Ignored files generated by later experiments are not part of the Git release;
do not upload the working folder indiscriminately. Pattern checks do not establish
complete source authorization or a comprehensive privacy/content audit.

## Optional source archive

A separate export is optional; it does not replace the in-place repository:

```bash
python scripts/build_release.py --output ../Poison-Detection-release --zip
python scripts/build_release.py --verify ../Poison-Detection-release
```

The builder refuses to overwrite an existing destination. Use a new destination
for a later candidate. It copies only the exact entries in `release_files.txt`,
rejects corpus/weight/restricted-code paths and symlinks, checks text files for
credential/email patterns, compiles Python syntax without execution, and records
SHA-256 hashes in `RELEASE_MANIFEST.json`. The verifier rejects missing, modified,
or additional files. It does not contact GitHub or publish anything.

To regenerate the numbered statement before building another candidate:

```bash
python -m pip install -r requirements-release.txt
python scripts/render_artifact_statement.py
```

`scripts/audit_artifacts.py --source-root /path/to/private-research-archive`
regenerates the aggregate statistics and screening report from the archived
records. It requires those excluded records and is not a data-download script.
The three files in `docs/aggregate_results/` are
unchanged copies of the historical per-seed summary CSVs.

The allowlist includes project code, dependency/configuration files, selected
documentation, aggregate study counts/results, this release statement and its
standalone PDF. Source exports exclude `.git`; the repository retains sanitized
code history. Both exclude all raw/rewritten datasets, cached prompts
and completions, model/tokenizer files, score arrays, row-level outputs, logs,
external repositories and `coling2027/_restricted_zscore.py`.

## Updating an existing GitHub repository

The local remote URL is preserved, but existing remote branches still require a
separate, coordinated update. Do not pull or merge old remote history into this
checkout. Before publishing, compare the remote branch tips with the saved
pre-cleanup tips and review every affected branch. Rewritten branches require
explicit, branch-specific `--force-with-lease` updates; an ordinary push does not
replace old history. This preparation does not run those updates.

Remote branches, tags, pull-request refs, releases, attachments, caches and forks
are outside a local verification. A force push alone may leave older content
accessible. Follow [GitHub's history-removal guidance](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/removing-sensitive-data-from-a-repository)
for applicable follow-up; support removal is subject to GitHub's eligibility rules.
Check the actual hosted artifact before applying the checklist answers to it.

## Privacy and objectionable content

Movie reviews and generated variants can contain identifying information,
profanity, or harmful descriptions. Public availability and the absence of
separate author metadata do not guarantee privacy. Dataset row IDs/hashes also
do not anonymize unchanged searchable text.

`scripts/audit_artifacts.py` screens two specified local clean training pools
and writes **only aggregate counts** to `docs/content_audit.json`. On 2026-10-12,
the 10,000-row IMDB pool produced seven email-format candidate rows and 49
profanity-keyword candidate rows; the 6,000-row SST-2 pool produced zero matches
for those particular patterns. These are unadjudicated flags, not proof of seven
identifiable people, a complete toxicity assessment, or absence of risk elsewhere.
The screening does not cover all names, addresses, obfuscated identifiers or
contextual harms.

The release mitigation is **data minimization**: the entire raw/derived text and
row-level output collections are absent from the public repository and its
sanitized history. The study's archived data
has not been rewritten or claimed to be fully anonymized; recorded experiments
therefore remain unchanged. The screening script necessarily contains detection
vocabulary in its pattern definitions, but no source review is included as an
example. Instructions, documentation and synthetic smoke inputs were reviewed
for embedded source text; repository history checks and export hashes verify the
release boundary.

New data exports would need source authorization and their own privacy/content
review. Local runs can regenerate problematic text; this public code release is
not a promise that generated data is suitable for unrestricted publication.

## Research use and limitations

The intended scientific use is controlled study of poisoned-data detection and
defenses. A suspicious score is a review signal, not evidence that a contributor
acted maliciously. Filtering can remove useful or minority-distribution examples.
Attack-generation utilities can support misuse, and results do not establish
adaptive robustness or general safety. This statement describes intended use;
it does not add a research-only restriction to the MIT license.
